# 시트 정리 프로그램

엑셀 파일 안에서 **RMA 시트의 특정 열들을 골라 다른 시트(SYSTEM 시트 등)로 옮겨주는** tkinter 기반 데스크톱 도구입니다.
셀 위치가 아니라 **열 이름**으로 매칭하기 때문에, 원본 시트에서 열 순서가 바뀌어도 결과가 깨지지 않습니다.

## 배경

- 원래는 `=IF(RMA!M3="","",RMA!M3)` 같은 수식으로 RMA 시트의 열을 SYSTEM 시트에 하나씩 옮겨 적었음
- 문제는 열 순서/이름이 자주 바뀐다는 것 — 셀 위치(M3 등)를 기준으로 한 수식이라 열이 하나만 옮겨져도 수식이 깨짐
- 그래서 셀 위치가 아니라 **열 이름 기준 매칭**으로 다시 설계하기로 결정
- 자동화 방법으로 엑셀 매크로(VBA)도 고려했지만, 최종적으로는 **파이썬 독립 프로그램(GUI)** 형태로 만들기로 결정
  (엑셀 파일/매크로 보안 설정에 영향받지 않고, 파일이 열려 있어도 미리보기가 가능한 등 다루기 편해서)
- 이후 실제 사용하면서 기능을 늘려왔음 (아래 "개발 히스토리" 참고)

## 이런 분께 필요합니다

- RMA(반품/수리) 시트에서 매번 같은 열들을 골라 다른 시트로 옮겨 적는 반복 작업을 하고 있다면
- 옮길 열이 이름/번호로 자주 바뀌어서 수식이 자꾸 깨진다면
- 엑셀을 열어둔 채로 결과를 먼저 확인하고, 확실할 때만 저장하고 싶다면

## 기능 요약

| 기능 | 설명 |
|---|---|
| 열 이름 기준 매칭 | 셀 위치가 아니라 헤더 이름으로 찾기 때문에 원본 열 순서가 바뀌어도 안전 |
| 열 선택 빌더 UI | 시트/열을 드롭다운에서 골라 "추가" 버튼으로 쌓는 방식 (직접 타이핑 안 함 → 오타 없음) |
| 출력 이름 바꾸기 | 원본이 `지역`이어도 결과 시트에는 `SITE`로 저장 가능 |
| 순서 변경 / 삭제 | 추가한 열 목록을 ▲▼로 순서 바꾸고, 선택 삭제 / 전체 지우기 가능 |
| 공백(스페이서) 열 | 데이터 없는 빈 열을 중간에 끼워 넣어 결과 시트 배치를 잡을 수 있음 (새 시트 모드 전용) |
| 시트별 헤더 행 기억 | 시트마다 헤더 행 번호가 달라도(2행 / 1행 등) 각각 기억해서 처리 |
| 새 시트 / 기존 시트 | 새 시트 생성(이름 중복 시 `_1`, `_2` 자동), 또는 기존 시트 아래에 이어서 추가 |
| 새 열 삽입 위치 지정 | 기존 시트에 없던 열을 맨 뒤가 아니라, 지정한 열의 앞/뒤에 끼워 넣기 |
| 서식 / 수식 복사 | 글자색·배경색·테두리·표시형식 복사 여부, 수식을 값이 아닌 수식 그대로 복사 여부 |
| 저장 전 미리보기 | 파일을 건드리지 않고 결과 표를 먼저 확인 (엑셀이 열려 있어도 가능) |
| 원본 시트 보기 | 아무 시트나 골라 행 번호/열 문자와 함께 실제 내용 확인 |
| 처리 로그 | 찾지 못한 열, 새로 추가된 열, 복사된 행 수 등을 모두 기록 |

## 실행 방법

### 1. 빌드된 exe로 실행 (Python 설치 불필요)

`dist/시트정리프로그램.exe` 를 더블클릭하면 바로 실행됩니다.

### 2. 소스로 직접 실행 (개발/수정 시)

```powershell
# 최초 1회: 가상환경 생성 + 라이브러리 설치
python -m venv .venv
.venv\Scripts\activate
pip install openpyxl

# 실행
python 엑셀_정리_프로그램.py
```

## 사용법

### 1. 엑셀 파일 선택

"찾아보기"로 RMA 시트가 들어있는 `.xlsx` / `.xlsm` 파일을 선택합니다.
선택하면 파일 안의 시트 목록이 바로 아래에 표시되고, 각 드롭다운도 자동으로 채워집니다.
(이름에 `RMA`가 들어간 시트가 있으면 그게 기본 선택됩니다.)

### 2. 원본 시트 설정 — "가져올 열" 만들기

목록을 **비워두면 기본 15개 열**을 이름으로 찾아서 사용합니다.

> No., 계약년, SYSTEM, 구분, 관리국, SITE, 품질개선팀, 유니트명, 삼성SN, PKG후장애, 고객 SN, 벤더SN, 입고일, 출고일, 수리년도

직접 고르려면 아래 순서로 한 줄씩 추가합니다.

1. **시트** — 열을 가져올 시트를 고릅니다.
2. **헤더 행** — 그 시트에서 열 제목이 있는 행 번호. (예: 2행에 제목이 있으면 `2` → 데이터는 3행부터)
   시트를 바꾸면, 그 시트에서 **마지막으로 썼던 헤더 행 번호를 자동으로 다시 불러옵니다.**
3. **열** — 위에서 지정한 헤더 행에서 **실제로 읽어온 열 제목** 중에서 고릅니다. (직접 타이핑하지 않음)
   목록이 비어 있거나 이상하면 헤더 행 번호를 고친 뒤 **새로고침**을 누르세요.
4. **출력 이름(선택)** — 비워두면 원본 열 제목 그대로 저장되고, 입력하면 그 이름으로 저장됩니다.
5. **추가** — 아래 목록에 `출력이름 ← 원본` 형태로 한 줄이 쌓입니다.

부가 기능:

- **공백 열 추가** — 데이터 없는 빈 열을 목록 중간에 끼워 넣습니다. 출력 이름을 적어두면 "제목만 있고 값은 비어있는 열"(수기 입력용)이 되고, 비워두면 완전히 빈 열이 됩니다.
- **▲ 위로 / ▼ 아래로** — 결과 시트에 나올 열 순서를 바꿉니다.
- **선택 삭제 / 전체 지우기** — 잘못 추가한 항목을 지웁니다.
- 목록 아래 라벨에 **기준 시트**와 **만들어지는 입력값**(내부적으로 로직에 넘어가는 문자열)이 항상 표시됩니다.

#### 기준 시트란

행을 몇 개 만들지, 어느 행을 건너뛸지를 결정하는 **처리의 기준이 되는 시트**입니다.
따로 고르는 칸이 없고, **목록에 가장 먼저 추가한 (빈 열이 아닌) 열의 시트**로 자동 결정됩니다.
목록이 비어 있으면 지금 '시트' 드롭다운에서 선택 중인 값이 기준 시트가 됩니다.

- 기준 시트를 바꾸고 싶으면 → 목록 맨 위에 그 시트의 열이 오도록 순서를 바꾸면 됩니다.
- 기준 시트에서 **첫 번째로 추가한 열이 비어있는 행은 건너뜁니다.** (빈 행 걸러내기 용도)

#### 다른 시트의 열을 섞어 쓸 때 (주의)

목록에 여러 시트의 열을 섞어서 추가하는 것 자체는 가능합니다. 다만 현재는 값으로 짝을 맞추지 않고,
**"기준 시트의 n번째 데이터 행 ↔ 다른 시트의 n번째 데이터 행"** 으로 그대로 이어 붙입니다.
따라서 **두 시트의 행 순서와 개수가 정확히 같을 때만** 결과가 맞습니다.
(다른 시트에 행이 모자라면 그만큼 비워두고 로그에 남깁니다.)

> 시트마다 행 순서가 다를 수 있는 경우를 위한 "행 맞춤(키 값 매칭)" 기능은 로직(`core.py`)에는 남아 있지만
> 화면에서는 빠져 있습니다. 실제 사용 방식과 안 맞아서 다시 설계 예정입니다.

### 3. 결과를 저장할 위치

- **새 시트 만들기** — 지정한 이름으로 새 시트를 생성합니다. (이름이 중복되면 자동으로 `_1`, `_2`가 붙습니다.)
  기본값은 오늘 날짜가 붙은 `SYSTEM_YYYYMMDD` 입니다.
- **기존 시트에 이어서 추가** — 기존 시트의 **1행을 헤더로 보고**, 이름이 같은 열 위치에 데이터를 이어서 채웁니다.
  - 마지막 행은 시트 전체가 아니라 **이번에 실제로 채우는 열들만 봐서** 찾습니다.
    (예: 예전에 SITE 열만 채웠고 이번엔 No./SYSTEM을 추가하는 경우, SITE에 데이터가 있어도 무시하고 빈 자리부터 채움)
  - 기존 시트에 **없던 열**은 기본적으로 맨 뒤에 추가됩니다.
    **새 열 삽입 위치**에서 기준 열을 고르고 "앞 / 뒤"를 선택하면 그 자리에 끼워 넣습니다.
    (이번 실행에서 새로 생기는 열들은 모두 그 한 지점에 묶여서 삽입되고, 기존 데이터는 오른쪽으로 밀립니다.)
  - **공백(스페이서) 열은 이 모드에서 지원하지 않습니다.** 재실행할 때 "같은 빈 열"을 다시 찾을 방법이 없기 때문이며,
    자동으로 건너뛰고 로그에 안내가 남습니다.

### 4. 복사 옵션

- **서식도 함께 복사** — 글자색/배경색/테두리/정렬/표시형식을 원본 셀 그대로 가져옵니다.
- **수식 자체를 복사** — 원본이 `=...` 수식이면 계산된 값 대신 수식 문자열 그대로 복사합니다.

### 5. 미리보기 / 실행

- **미리보기 (저장 안 함)** — 파일을 저장하지 않고 결과를 화면 표로 먼저 확인합니다.
  **엑셀에서 파일을 열어둔 상태에서도 항상 가능합니다.** 최대 200행까지 보여줍니다.
  이번에 실제로 값이 채워지는 열은 제목에 `★`가 붙고, 그 열로 자동 스크롤됩니다.
- **실행 (실제 저장)** — 원본 파일에 그대로 저장합니다.
  ⚠️ **이때는 엑셀에서 해당 파일을 반드시 닫아둬야 합니다.** 열려 있으면 저장 시 오류가 납니다.
  저장이 끝나면 시트 목록/드롭다운/원본 보기 탭이 자동으로 새로고침됩니다.

### 6. 탭 3개

- **원본 시트 보기** — 아무 시트나 골라 엑셀처럼 행 번호/열 문자와 함께 실제 내용을 봅니다. (최대 300행, 수식은 계산된 값으로)
- **결과 미리보기** — 미리보기 결과 표.
- **처리 로그** — 못 찾은 열, 새로 추가된 열, 복사된 행 수, 건너뛴 항목 등이 시간과 함께 기록됩니다.

두 표 모두 행을 클릭하면 그 행 전체 내용이 아래에 펼쳐지고, `Shift + 마우스 휠`로 좌우 스크롤이 됩니다.

## 내부 동작 (열 지정 문자열 문법)

화면에서 만든 열 목록은 내부적으로 콤마로 구분된 문자열 하나로 바뀌어 `core.py`에 전달됩니다.
(화면 아래 "만들어지는 입력값" 라벨에 그대로 표시되는 값입니다. 직접 쓸 일은 없지만, 로그를 읽거나 로직을 테스트할 때 알아두면 편합니다.)

한 토큰의 형태: `[출력이름=] [시트이름!] 원본식별자`

| 입력 | 의미 |
|---|---|
| `SITE` | 기준 시트에서 `SITE` 열을 찾아 그 이름 그대로 출력 |
| `1` 또는 `A` | 기준 시트의 1번째 열 / A열 (이름 대신 번호·열 문자도 가능) |
| `SITE=지역` | 기준 시트의 `지역` 열을 가져와 출력 이름은 `SITE` |
| `SITE=관리표!지역` | `관리표` 시트의 `지역` 열을 가져와 출력 이름은 `SITE` |
| (빈 토큰) | 이름도 데이터도 없는 스페이서 열 |
| `비고=` | 제목만 있고 데이터는 없는 열 (수기 입력용) |

시트마다 다른 헤더 행 번호는 별도로 `{시트이름: 헤더행}` 형태로 함께 전달됩니다.

## 파일 구조

```
엑셀_정리_프로그램.py   GUI (tkinter) - 화면 구성, 사용자 입력, 열 목록 빌더, 버튼 동작
core.py                핵심 로직 - 엑셀 읽기/쓰기, 열 이름 매칭, 데이터 복사 (GUI에 의존하지 않음)
test_core.py           core.py 단위 테스트 (pytest)
시트정리프로그램.spec   PyInstaller 빌드 설정
dist/                  빌드된 exe (git 추적 대상 아님)
build/                 PyInstaller 빌드 중간 산출물 (git 추적 대상 아님)
```

로직(`core.py`)과 화면(`엑셀_정리_프로그램.py`)을 분리해둔 이유는, 앞으로 기능이 늘어날 때
화면 코드를 건드리지 않고 로직만 수정/테스트할 수 있게 하기 위해서입니다.

### core.py 주요 함수

| 함수 | 역할 |
|---|---|
| `parse_column_spec(spec_text)` | 열 지정 문자열을 토큰으로만 파싱 (시트 조회 없음) |
| `resolve_column_plan(...)` | 토큰을 실제 워크북에 맞춰 `(출력이름, 시트, 열번호)` 목록으로 해석 |
| `iter_matched_rows(...)` | 기준 시트를 행 단위로 돌면서 각 열이 읽어올 셀 위치를 만들어 냄 |
| `compute_result_rows(...)` | 저장하지 않고 결과 헤더/행만 계산 (미리보기용) |
| `run_conversion(...)` | 실제로 시트를 만들거나 채우고 파일에 저장 |
| `get_sheet_names` / `get_sheet_headers` / `read_raw_sheet` | 화면의 드롭다운·원본 보기용 조회 함수 |

## 테스트 실행

```powershell
pip install pytest
pytest
```

`test_core.py`에 열 파싱, 열 해석, 시트별 헤더 행 처리, 행 매칭, 서식/수식 복사, 기존 시트 중간 삽입(e2e)까지
29개 테스트가 있습니다. 화면 없이 함수 단위로 확인합니다.

## exe 빌드 방법

```powershell
pip install pyinstaller
pyinstaller --onefile --windowed --name "시트정리프로그램" 엑셀_정리_프로그램.py
```

- `--onefile`: 파일 하나로 압축 (같은 폴더의 `core.py`는 자동으로 함께 포함됩니다)
- `--windowed`: 실행 시 콘솔창 없이 GUI 창만 뜸
- 완료되면 `dist\시트정리프로그램.exe` 생성됨
- `build` 폴더는 매번 새로 생기는 중간 산출물이라 지워도 무방합니다
- 백신이 처음 보는 exe를 경고할 수 있습니다 → 예외 처리 또는 IT 담당자 확인 필요

## 자주 겪는 상황

| 증상 | 원인 / 해결 |
|---|---|
| '열' 드롭다운이 비어 있음 | 헤더 행 번호가 틀림 → 번호를 고치고 **새로고침** |
| 실행 시 저장 오류 | 엑셀에서 그 파일이 열려 있음 → 닫고 다시 실행 (미리보기는 열려 있어도 가능) |
| 결과 행이 예상보다 적음 | 기준 시트에서 **첫 번째로 추가한 열**이 비어있는 행은 건너뜀 |
| 다른 시트 값이 엉뚱하게 들어감 | 두 시트의 행 순서/개수가 다름 → 현재는 n번째 행끼리 그대로 이어 붙임 |
| 빈 열이 결과에 없음 | "기존 시트에 이어서 추가" 모드에서는 스페이서 열 미지원 (로그 확인) |

## 개발 히스토리 (요약)

1. **v1**: 고정된 15개 열을 새 시트에만 생성하는 기본 버전
2. **v2**: 열 이름/번호/문자로 원하는 열 직접 지정, 기존 시트에 이어 붙이기, 수식/서식 복사 옵션 추가
3. **v3**: 미리보기 기능(저장 전 결과 확인), 원본 시트 보기 탭, 시트 목록 자동 동기화, 실행 후 자동 새로고침
4. **버그 수정**: "기존 시트에 이어서 추가" 시 다른 열 데이터 때문에 행이 밀리던 문제 → 이번에 실제로 채우는 열 기준으로만 마지막 행을 찾도록 수정
5. **로직/GUI 분리 + 자유도 확장**: `core.py`(로직)와 `엑셀_정리_프로그램.py`(GUI) 분리, 단위 테스트 도입. 출력 열 이름 직접 지정(`SITE=지역`), 다른 시트 열 참조(`시트!열`), 빈 스페이서 열, 기존 시트 중간에 새 열 삽입 기능 추가
6. **열 선택 UI화**: "가져올 열"을 텍스트로 직접 타이핑하던 방식(오타 위험) 대신, 시트/열을 목록에서 선택 → 추가 버튼으로 쌓는 빌더 UI로 전환. 추가한 항목은 삭제·순서 변경 가능
7. **시트별 헤더 행 지원**: 시트마다 헤더 행 번호가 다를 때 다른 시트의 열을 못 찾던 문제 수정 (시트별 헤더 행을 기억해서 각각 적용)
8. **UI 단순화**: 빌더에 이미 시트를 고르는 칸이 생기면서 중복되던 "가져올 시트 이름" 칸 제거 (기준 시트는 목록의 첫 열에서 자동 결정). "행 맞춤 기준 열"(다른 시트 간 키 값 매칭)은 실제 필요와 안 맞아 화면에서 제거 — 로직은 남겨두고 나중에 재설계 예정
